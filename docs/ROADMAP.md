# Roadmap

## Milestone 0: Discovery and architecture validation
- Inspect repository and current files.
- Confirm stack or determine whether the repository is empty.
- Inspect the complete 170 Protocol Manual and build a verified protocol inventory.
- Verify current official Google image and video API documentation.
- Produce provider capability matrix, architecture recommendation, risks, and implementation plan.
- Obtain owner approval for material architecture choices.

Exit criteria: no invented provider capabilities, source manual inventory is traceable, architecture and stack decision are documented.

## Milestone 1: Application foundation
- Create the minimum viable application structure.
- Add configuration and secure credential handling foundations.
- Add persistence schema and migrations.
- Add project and workspace navigation.
- Add automated checks and development instructions.

## Milestone 2: Projects and production brief
- Create and manage projects.
- Capture image and video briefs.
- Add reference asset handling.
- Normalize brief data and constraints.

## Milestone 3: Google image generation
- Implement the verified Google image adapter.
- Validate capability and request parameters.
- Add explicit approval and safe job handling.
- Persist and preview image assets.

## Milestone 4: Video planning and Google video generation
- Add shot planning and continuity model.
- Implement the verified Google video adapter.
- Support asynchronous job status and safe recovery.
- Persist and preview video assets.

## Milestone 5: Quality review and iteration
- Add image and video quality findings.
- Add targeted revision flow.
- Preserve version history and plan traceability.

## Milestone 6: Delivery and release readiness
- Add export and metadata.
- Complete security, accessibility, and reliability review.
- Document deployment, operations, and known limitations.

## Later candidates
Additional providers, team collaboration, advanced asset organization, 3D/CGI, audio, editing timelines, and publishing integrations require separate prioritization and owner approval.

## Milestone report format
- Milestone and status
- Tasks completed
- Files changed
- Tests run and results
- Risks and unresolved questions
- Remaining tasks
- Completion percentage
- Next action
